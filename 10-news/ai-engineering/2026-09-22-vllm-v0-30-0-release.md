# vLLM v0.30.0: Fast Start weight cache, watermarking, breaking changes

## Summary

- vLLM v0.30.0 released 2026-09-22: 762 commits from 315 contributors.
- It includes **breaking changes** for `vllm serve` flags, GPTQ and several env vars.
- New features: a "Fast Start" GPU weight-cache daemon for fast engine restarts, and Gumbel-max watermarking.

## What Happened

- New models: DeepSeek-V4.1-Flash, GLM-5.3-Flash, K2-Horizon, Cohere Compass and others.
- **Fast Start** (`--load-format ipc_cache`): keeps quantized, TP-sharded weights in GPU memory so restarted engines map them over CUDA IPC instead of reloading from disk.
- **Watermarking:** Gumbel-max watermarked generation and detection, compatible with speculative decoding.
- **Speed claims** (release notes, not independently verified): engine init 28.9s → 8.2s on H200, from freezing gc during CUDA graph capture.

## What Changed — Breaking

- Scale-out endpoints are now opt-in via `--enable-scale-out`. This replaces the `VLLM_ENABLE_SCALE_OUT_ENDPOINTS` env var.
- GPTQ activation ordering (`g_idx`) is removed.
- Removed env vars: `VLLM_PREFIX_CACHE_RETENTION_INTERVAL`, `VLLM_MM_HASHER_ALGORITHM`.
- Deprecated:
  - `python -m vllm.entrypoints.grpc_server`, replaced by `vllm serve --grpc`
  - the `all` Mamba cache mode
- YaRN is aligned with Transformers: vendor YaRN aliases no longer re-scale `max_model_len`.

## Why It Matters

- Breaking flag and env-var changes will break existing deployment configs on upgrade.

## Practical Impact

- Before upgrading any vLLM deployment, check the flags and env vars listed above.
- The default wheel targets CUDA 13.0. CUDA 12.9 is available via separate images and wheels.
